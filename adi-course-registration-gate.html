Integration — Portal Source Code

Four steps to wire the Course Registration Gate into the ADI portal. No backend changes are required for the front-end lock; the finance-confirmation endpoint call shown in Step 3 is the only server-side touch.

1
Paste both patch scripts before </body>
Include the payment auto-fill patch (v1.1) and the new course gate script:
<!-- ADI Payment Auto-Fill Patch v1.1 -->
<script src="adi-payment-autofill-patch.js"></script>

<!-- ADI Course Registration Gate v1.0 -->
<script src="adi-course-registration-gate.js"></script>
</body>
2
Add data attributes to the registration page template
The gate auto-wires itself to any element carrying a data-adi-course-gate attribute:
<!-- Status banner injects here automatically -->
<div data-adi-course-gate="banner"></div>

<!-- Enrol button is disabled until gate opens -->
<button data-adi-course-gate="guard"
        class="btn-register"
        onclick="submitCourseEnrolment()">
  Register Selected Courses
</button>
3
Call confirmPayment() from the finance confirmation endpoint
When the Finance Office approves a payment in the admin panel, call:
// In the portal's finance admin confirmation handler:
function onFinanceConfirm(paymentRecord) {
  // key: 'registration' | 'platform'
  window.adiCourseGate.confirmPayment(
    paymentRecord.key,    // 'registration' or 'platform'
    paymentRecord.txId    // MoMo transaction ID
  );
  // Gate re-evaluates and fires 'adi:gate:open' if both are now confirmed.
  // All guarded buttons enable and all banners update automatically.
}
4
Guard the course enrolment API call server-side too
The front-end gate is UX enforcement. Add a server-side check in the course enrolment API route so a student cannot bypass it via direct API call: 
// Server-side (Node / Express example):
app.post('/api/enrol-courses', async (req, res) => {
  const student = await getStudent(req.user.id);

  const hasReg = student.payments.find(
    p => p.type === 'registration' && p.confirmed
  );
  const hasPlatform = student.payments.find(
    p => p.type === 'platform' && p.confirmed
  );

  if (!hasReg || !hasPlatform) {
    return res.status(403).json({
      error: 'GATE_LOCKED',
      message: 'Registration Fee and Platform Charge must be confirmed before course enrolment.'
    });
  }
  // ... proceed with enrolment
});
5
Listen for gate events in existing portal code
Subscribe to DOM events to react anywhere in the portal when the gate opens or closes:
document.addEventListener('adi:gate:open', function(e) {
  // e.detail = { open: true, paid: [...], missing: [] }
  showCourseRegistrationSection();
  adiNotify('portal',
    'Enrolment Unlocked',
    'Your payments have been confirmed. You may now register your courses.'
  );
});

document.addEventListener('adi:gate:locked', function(e) {
  hideCourseRegistrationSection();
});
Integration with Notification Engine v3.1 — The gate fires adi:gate:open which you can pass straight to window.adiNotify('portal', title, body) to send the student a chime + vibration the moment Finance confirms their payment.
